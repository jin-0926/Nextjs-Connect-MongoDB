# ✨ 프로젝트 개선 및 오류 수정 계획

## 📋 현재 진행 상황 요약
현재 장바구니 결제 로직에서 주문 내역(Order) 생성이 누락되어 있으며, 재고 및 판매자 권한 관련 필터링이 필요한 상태입니다.

---

## ✅ To-Do List

### 1. 주문 생성 기능 복구 및 고도화
- [ ] **결제 시 주문 데이터 생성**: `app/api/checkout/route.ts`에서 결제 성공 시 `OrderRepository.createOrder()`를 호출하여 실제 주문 내역을 DB에 저장하도록 수정합니다.
- [ ] **본인 상품 구매 제한**: 장바구니 아이템 중 판매자의 ID가 현재 로그인한 사용자의 ID와 일치할 경우 결제를 차단하는 로직을 추가합니다.

### 2. 재고 관리 및 상품 노출 로직 수정
- [ ] **품절 상품 숨기기**: `app/api/goods/route.ts`의 `GET` 요청 시 재고(`stock`)가 0보다 큰 상품만 반환하도록 `GoodsRepository`의 쿼리를 수정합니다.
- [ ] **메인 페이지 연동**: 재고가 없는 상품은 메인 리스트에서 제외하거나 '품절' 표시가 나타나도록 처리합니다.

### 3. 판매자 관리 기능 강화
- [ ] **상품 삭제/판매 중지 기능**: 판매자가 등록한 상품을 삭제하거나 비활성화할 수 있도록 `app/api/seller/goods/[id]` 엔드포인트를 구현합니다.
- [ ] **삭제 UI 추가**: 판매자 대시보드(`app/seller/page.tsx`)에 각 상품별 '삭제' 또는 '판매 중지' 버튼을 추가합니다.

### 4. 테스팅 및 검증
- [ ] **주문 내역 확인**: 상품 구매 후 판매자 페이지(`app/seller/orders`)에 주문 정보가 정상적으로 노출되는지 확인합니다.
- [ ] **재고 차감 검증**: 구매 완료 후 `Goods` 컬렉션의 `stock` 필드가 정확히 차감되는지 확인합니다.

## 🛠 코드 분석 결과 요약

| 문제점 | 원인 | 해결 방안 |
| :--- | :--- | :--- |
| **주문 내역 안 뜸** | `checkout` API에서 `Order` 생성 로직 누락 | `OrderRepository.createOrder` 연동 |
| **자기 상품 구매 가능** | 체크아웃 전 본인 상품 여부 확인 로직 부재 | `sellerId`와 `userId` 비교 검사 추가 |
| **재고 0 상품 노출** | `getAllGoods`에서 재고 필터링 누락 | `stock: { $gt: 0 }` 조건 추가 |
| **상품 삭제 불가** | DELETE API 및 UI 버튼 미구현 | 판매자 전용 삭제 API 및 UI 버튼 구현 |
